## Задание 1. Исследование моделей и инфраструктуры

## 1. Сравнение LLM-моделей

| Критерий | Hugging Face (локальные) | OpenAI API | YandexGPT |
|----------|-------------------------|------------|-----------|
| Качество ответов | Зависит от модели. Самые мощные модели приближаются к облачным, но всё равно проиграют, и при этом потребуют огромной инфраструктуры и железа. Язык также зависит от модели | Наилучшее, флагман. Полная поддержка мультиязычности. | Высокое, активно развивается. По языкам акцент на RU и EN |
| Скорость работы | Зависит от железа. В общем случае ниже, но при внушительных вложениях в память и GPU может оказаться сопоставимым или выше (за счет аналогичного железа относительно облачного, но отсутствия необходимости вызывать API и сетевых задержек) | Очень высокая, передовое железо. Есть ограничения на rate limits (при больших количествах запросов) | Очень высокая, передовое железо. Есть ограничения на rate limits (при больших количествах запросов) |
| Стоимость владения | Основные затраты: разовые (покупка железа) и периодические (поддержка инфраструктуры, оплата электроэнергии, зарплаты девопсам, инженерам и т.д.). При увеличении запросов и планов железо нужно будет обновлять | Основные затраты периодические - оплата подписки. При повышенных запросах - дополнительная оплата токенов | Основные затраты периодические - оплата подписки. При повышенных запросах - дополнительная оплата токенов. Подписка и токены в разы дешевле, чем у OpenAI |
| Развёртывание | Сложность на порядок сложнее облачного. Самостоятельное развёртывание инфрмаструктуры, обеспечение мониторинга и безопасности, последующая поддержка стабильности и отказоустойчивости. Намного больше требуется времени на развёртывание | Просто начать пользоваться | Просто начать пользоваться |
| Безопасность и соответствие | Полный контроль над данными, т.к. сё остается внутри своего же контура. За безопасность и соответствие SOC 2 полностью самостоятельная ответственность | Есть сертификация SOC 2 | Есть сертификация SOC 2 |

Из-за работы с конфиденциальными данными клиентов и международной направленности компании необходимо использовать локальную модель. В частности, подойдёт одна из последних моделей Qwen3-30B-A3B - мультиязычная, 30 миллиардов параметров.
При этом не стоит исключать и подключение облачных вариантов. YandexGPT не подойдет, т.к. скандинавские языки не являются приоритетами в разработке данной системы. МОжно использовать OpenAI API для двух вариантов:
- пока закупается и настраивается железо, можно потестировать MVP на своей технической документации (удаление дублей, систематизация базы знаний)
- дальнейшая работа с пользователями по запросам, не использующим конфиденциальные данные

### Рекомендуемый вариант

Начать с MVP на внутренние команды - локальная модель В ОБЛАКЕ + OpenAI API для общих вопросов. Опробовать все гипотезы, понять востребованность у пользователей, понять дальнейшие планы по проекту. По результатам рассчитать прибыль от фичи, затраты на железо в облаке и потенциальные затраты на закупку и поддержку локального железа. По результатам зафиксировать один из следующих вариантов:
- оставить всё как есть. Аренда и железа (Azure, GCP и т.д.), и ИИ (OpenAI) будет выгоднее, своё железо не окупится исходя из планов продукта. При этом фича рентабельна для внутреннего и потенциально внешнего использования.
- закупить локальное железо. Фича окупит эти вложения, при этом использование сторонних ресурсов в долгосроке встанет компании дороже.
- отключить функционал. Разово привели в порядок документацию, дальше использование бота нерентабельно, внешние клиенты не заинтересованы. При необходимости установить периодичность, с которой функционал будет включаться, систематизировать новые знания, и отключаться

## 2. Сравнение моделей эмбеддингов

| Критерий | Sentence-Transformers (локальные) | OpenAI Embeddings |
|----------|-----------------------------------|-------------------|
| Скорость создания индекса | Низкая (в разы) для CPU, сопоставимая с облачными для GPU | Быстрая, но можно упереться в API лимиты |
| Качество поиска | Зависит от модели - от точности до поддержки многоязычности. На максимальном железе будет сопоставимо с облачным решением | Высокая |
| Стоимость владения и использования | Единоразовые затраты на инфраструктуру | В зависимости от подписки/тарифа |

### Рекомендуемый вариант

Использовать локальный Sentence-Transformers - качество сопоставимо с OpenAI, но т.к. в любом случае будем разворачивать инфру для Qwen3, нет смысла переплачивать. Один из вариантов - gte-multilingual-base - оптимально по скорости и качеству, и поддерживает финский и эстонский для локального тестирования (и при дальнейшей раскатке на внешних пользователей будет удобен)

## 3. Сравнение векторных баз данных

| Критерий | FAISS | ChromaDB |
|----------|----------|-------|
| Скорость поиска и индексации | Высокая | Средняя |
| Сложность внедрения и поддержки | Низкая (pip install), требования минимальные. Поддержка чуть сложнее (своя настройка мониторинга) | Низкая (pip install), требования минимальные |
| Удобство в работе | Функциональности "из коробки" меньше, но больше возможностей масштабирования (большее количество векторов, горизонтальное масштабирование) | Функциональности "из коробки" больше (SQLite, хранение документов), но меньше возможностей масштабирования |
| Стоимость владения | Требования к железу чуть ниже | Требования к железу чуть выше |

### Рекомендуемый вариант

Чуть лучше будет вариант с ChromaDB. Скорость поиска на нашем объеме документов и поддержка миллиардов векторов на наших объемах не так важна, а чуть более удобная настройка с встроенными инструментами будут важнее при использовании.
